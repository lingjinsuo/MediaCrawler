## 1. 项目背景与目标

### 1.1 背景

本项目基于开源项目 **MediaCrawler**（多平台社交媒体数据采集框架）进行二次开发，面向**电商运营 / 品牌市场**场景，构建一套「**多平台内容采集 → 评论意图识别 → 线索推送 → 数据洞察**」的闭环系统。

目标用户是电商运营与客服团队：他们需要在小红书、抖音、快手等平台发现「求链接、问价格、想买」等**高价值购买意图评论**，并及时跟进转化；同时需要看清各平台、各关键词的热度分布，用于选品与内容投放决策。

### 1.2 总体目标

1. **采集自动化**：运营无需编写代码，在 Web 控制台点选平台/关键词即可完成一轮采集，7 平台统一入库。
2. **意图识别自动化**：系统按运营维护的关键词词库，自动识别评论是否具备购买意图，命中即进入推送池。
3. **线索可跟进**：推送线索支持筛选、检索、批量处理，形成「待处理 → 已处理」的工单闭环。
4. **数据可洞察**：提供帖子/评论的统一浏览视图与趋势看板，支撑投放决策。
5. **系统可长期运行**：解决抖音等平台的风控对抗问题，具备部署、监控、告警能力，可 7×24 稳定运行。

### 1.3 非目标（本期不做）

- 不做多租户 SaaS 化改造与在线计费。
- 不做视频/图片素材下载与媒资管理（`ENABLE_GET_MEIDAS` 保持关闭）。
- 不做用户行为画像、达人生态分析等衍生产品。
- 不做面向 C 端的公开检索门户。

## 8. 验收标准

### 8.1 功能验收
1. 7 个平台均可在控制台完成「配置 → 采集 → 入库 → 意图识别 → 线索推送」全链路，无人工干预。
2. 线索池支持按平台、状态、时间区间、关键词筛选与检索，分页准确。
3. 数据浏览页可正确展示帖子与评论嵌套关系，原帖详情可查。
4. 关键词词库修改后无需重启即在下轮跑批生效。

### 8.2 质量验收
1. `pytest tests/` 全部通过，通过率 100%。
2. CI 流水线在每次提交上运行，PR 未全绿不允许合并。
3. 抖音平台单轮采集成功率 ≥ 90%，风控触发后可自动恢复。
4. 7 平台端到端业务验收全部留存记录，无 P0/P1 遗留缺陷。

### 8.3 安全验收
1. 仓库与镜像中不含有效凭据（Cookie / 密码 / API Key）。
2. 所有 `/api/**` 端点默认鉴权，越权访问返回 401/403。
3. 输出数据不含可识别个人身份信息，脱敏规则通过专项用例。

### 8.4 上线验收
1. 部署方案可一条命令拉起，含依赖中间件。
2. 监控告警生效，服务异常 5 分钟内可触达。
3. 灰度上线试运行 ≥3 天，无 P0 故障。
4. 运维手册、接口文档、数据字典齐备。
